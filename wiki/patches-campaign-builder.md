# Patches: campaign builder and campaign pages

The campaign builder canvas (overlay, pan, wait strip, disconnect button, circles of the nodes). The campaign page order and the wide event modal: wiki/patches-campaign-pages-and-modals.md. The counts of a node and the tooltips of its buttons: wiki/patches-campaign-node-ui.md.

## What it does

Listeners are on the document, capture phase, once (window.mauticPatchesCanvasPan), so ajax-loaded pages work. The new function removes every Label overlay through Object.keys, then calls window.mauticPatchesSetWait(node, text, lines) with the text core already put in Mautic.campaignBuilderLabels. The text only exists in the builder (core builds it in EventController / CampaignController, the campaign page's data has trigger mode, interval and unit but no text), so the Preview tab gets it from CampaignPreviewWaitSubscriber: on 'tabs.content' it builds the text with core's own translation keys and arguments (interval and date, '_inaction' for the no path) and leaves it in window.mauticPatchesPreviewWaits; window.mauticPatchesApplyWaits puts it on the nodes now and after every Mautic.onPageLoad (content loaded over ajax is NOT in the page when its inline script runs, so an inline script alone fails there). The no path of a CONDITION keeps the plain text ('esperar 1 dia'), not core's '_inaction' one ('entre 1 dia'): core picks the text only by the path, but 'entre' is the deadline of a DECISION's no path (InactiveExecutioner), while a condition is evaluated once, at once (ConditionExecutioner) and its no path waits like any event.
