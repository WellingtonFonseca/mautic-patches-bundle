## Segment: including / excluding on text fields (chips)

Several values in ONE criterion instead of one criterion per value joined by OR (which forces repeating every other filter).

```json
{
  "operator": "core offers `in` / `!in` (including / excluding) only on lists (select, country...). EventListener/SegmentTextInOperatorSubscriber (LIST_FILTERS_CHOICES_ON_GENERATE, priority -100) adds them after `!like` on contact and company fields of type text, email, tel, url, textarea, phone. Custom Object fields get the same from the Custom Objects plugin. `in` on a text column already works in the segment query.",
  "value format": "the filter's value is one string, values joined with `|` (A|B|C). Core splits it. A comma or semicolon does NOT split (`a,b` is the literal text). Equals / regexp / like keep `|` as part of the value. Core's value input for `in` on text is a plain text input (#leadlist_filters_N_properties_filter); core also turns pasted new lines into `|` there.",
  "chips component": "Resources/js/segment-in-chips.js (inlined by EventListener/SegmentInChipsSubscriber on page.header.left; its logic is tested in Node, the DOM part only in a browser). It replaces that input by chips: Enter adds the typed text even if it is not in the suggestions, paste splits on new lines / tabs / `|`, `x` or Backspace removes, blur keeps what is typed. The real input stays hidden and holds the joined value, so server and saved segments do not change. The chips use core's `label label-gray`. Padrão: [ui-theme.md](ui-theme.md) (label-gray, not label-default). It re-scans after every ajax call (the input is replaced whenever the operator or field changes) and opens an existing A|B|C as chips.",
  "copy button": "the chips box sits in a core `input-group` with a `span.input-group-addon.postaddon` (icon `ri-file-copy-line`, `ri-check-line` for 1.5 s after copying) that copies the values one per line; pasting them back into the chips gives the same values.   "ui pattern rule": "a new control must follow core / the other plugins: a button at the end of a field is an input-group postaddon with an `ri-*-line` icon (as the eye of the n8n token and the open-image button of the HSM carousel; core markup in mautic_form_layout.html.twig form_widget_simple).   "suggestions": "contact and company: GET /s/segment-filter-values?object=lead|company&field=<alias>&q=&limit= (Service/SegmentFilterValues: distinct values of a registered text field, LIKE with wildcards escaped, limit capped at 50, needs lead:leads:viewown or viewother; 404 for anything else).
```
