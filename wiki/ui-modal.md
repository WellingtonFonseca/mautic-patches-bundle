categoria: ui
regras:
- Confirmation modal (every core delete, deactivate a campaign, cancel a scheduled event, delete a field): the buttons are in `.modal-footer .modal-form-buttons`, the ACTION (#confirm) first, Cancelar last (btn-tertiary btn-cancel), each with its icon at the end (a bin for btn-danger, a check for another action, ri-close-line for Cancelar).
- Confirmation modal CSS: `.confirmation-modal .modal-content` padding 0, overflow hidden and the radius `--border-radius-lg` of the other modals (core's `padding: 8px` left the footer buttons 8px short of the edges); `.modal-footer` padding 15px (core's 16px left a 1px edge), text left and regular weight; the red action's text and icon are white in the light themes and black in the dark ones, as the Delete item of the row menus.
- Footer buttons of a modal form (Save, Save & Close, Close) share the whole footer equally: `:root .modal-footer .modal-form-buttons .btn{flex:1 1 0;width:auto}` (core gives every .btn a fixed width; only a lone button grows); the footer's gap and the rounded outer corners of the first / last button stay core's. Applies to EVERY modal with form buttons.
- A modal that shows another screen in core's shared modal (#MauticSharedModal, Mautic.ajaxifyModal) puts its buttons in a `.bottom-form-buttons` block: core COPIES it into the footer and hides the original (so find a button by id at use time). Order: the action first (Edit), the secondary (Details), Close last (btn-tertiary btn-cancel). The n8n template modals use the same footer (Edit first, Close last).
- Keep a single `.btn-primary` in a footer: core's CSS draws the SECOND .btn-primary (and a btn-secondary after two) as outlined / tertiary by POSITION: Edit btn-primary, Details btn-secondary, Close btn-tertiary btn-cancel (the transparent look). Buttons that never show together (Recalculate, Apply) each sit in their own parent.
- Width: the modals that hold a table (contact details, segment details, campaign event, n8n Dispatches) are 1100px (`max-width:95vw`), by a `:has` style on the modal-dialog for that modal only; the width follows the content.
- The shared modal's body already has side padding: a `.tab-content` inside it uses `pt-md`, not core's `pa-md` (it doubled the padding); the table must not touch the tabs (gap >= 10px).
- Long text (a filter value or a column with no space) must not grow a table inside a modal: `td` and `th` get `overflow-wrap:anywhere` and the cells of `#leadTable` `white-space:normal`; core sets nowrap by the id `#leadTable` and overflow-wrap does nothing on nowrap, so that selector needs the id to win.
- A modal built by a third-party script (GrapesJS `.gjs-mdl-dialog`): the rules start with `:root` to win over its classes, use `var(--background)` and `var(--text-primary)` so both themes follow, and never use innerHTML with server text (build text nodes).
- A browser spec that sets the theme must do it AFTER opening the modal (opening can load the page again and the attribute is lost).
